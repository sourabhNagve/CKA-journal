# 1. Exam Scenario

Task:
A deployment named `log-processor` was recently deployed into the `telemetry` namespace. This deployment utilizes an init container to bootstrap configuration, an application container to generate data, and a sidecar container to ship logs.

However, the operations team has reported that the deployment is completely broken. When they run `kubectl get pods -n telemetry`, no pods are appearing. 

Troubleshoot and resolve all issues preventing the `log-processor` from running successfully. 

When fully operational:
1. Exactly one `log-processor` pod should be in the `Running` state.
2. The `shipper` sidecar container must successfully output the log lines generated by the `app` container to standard output (`stdout`).

# 2. Initial Cluster State

- **Namespaces:** `telemetry`
- **Deployments:** `log-processor` (in `telemetry`)
- **ConfigMaps:** `log-config` (in `telemetry`)
